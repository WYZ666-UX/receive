## 3. 新增命令 `SET_TESTPAT`（`0x15` / `0x95`）

**完整规格见 `双端通信协议规范-20261101.md` §10。** 这里只给实现要点：

```
显示端 → 采集端：  A5 5B 01 15 01 CRC16        开测试图案
采集端 → 显示端：  A5 5B 01 95 01 CRC16        回实际生效值

显示端 → 采集端：  A5 5B 01 15 00 CRC16        回真实 ADC
采集端 → 显示端：  A5 5B 01 95 00 CRC16
```

| 规则 | 行为 |
|---|---|
| `0` | 真实 ADC + GPIOB->IDR |
| `1` | 测试图案，**缓冲立即填充**，每帧内容相同 |
| 其它值 | 保持当前，`ACK_TP` 回实际值（**不 NACK**）|
| `LEN=0` | `NACK 0x02` |
| 不支持 | `NACK 0x04` |

**切换立即生效**，不需要等帧边界（图案是静态的）。

**`CAP` 不用改** —— `CAP` 第 4 位（`0x10`）本来就宣告了这项能力，此前只是缺命令码。

## 4. ★ 标准答案（验收就比这两个数）

`SET_TESTPAT 1` 之后，对**解出来的 1250 字节载荷**（帧内偏移 `20..1269`）
算 CRC32（标准 zlib / `binascii.crc32`）：

| PART | 覆盖点 | 载荷长度 | **CRC32** |
|---|---|---|---|
| `0` | `k = 0..249` | 1250 B | **`0xAA003E01`** |
| `1` | `k = 250..499` | 1250 B | **`0x753D82DE`** |

```python
import binascii
ok = (binascii.crc32(payload) & 0xFFFFFFFF) == (0xAA003E01 if part == 0 else 0x753D82DE)
```

### 这两个数对上的含义

**下列各项全部正确，不需要再就它们做任何沟通**：

- 载荷是**两块连续**（模拟 `20..1019` / 数字 `1020..1269`），不是逐点交织
- 模拟块内部 **CH1 在前、CH2 在后**
- 16 位**小端**字节序
- 数字块起始偏移 **1020**
- 数字位打包 **bit0=D1 / bit1=D2 / bit2=D3**
- PART0 = `k 0..249`，PART1 = `k 250..499`

### 对不上时的定位表

| 现象 | 原因 |
|---|---|
| 第 0 点 `CH1 = 2048`（期望 `0`）| 模拟块内部 CH1/CH2 顺序反了 |
| 前 250 点对、后 250 点乱 | PART 划分或窗口起点错 |
| 数字块全 `0` 或全 `FF` | 数字块偏移不是 1020 |
| 波形整体偏移 1 点 | 窗口起点差 1 |
| `CH1` 约为期望的一半 | 按 8 位而不是 16 位读 |

**前 16 点精确值表在协议规范 §10.4。**

## 5. 原 9 个 `【待确认】` 全部转成判据

**左边是你们文档里的待确认项，右边是替代它的自测。全部对端可以独立完成。**

| 原待确认 | 判据（30 秒内可完成）| 期望结果 |
|---|---|---|
| **Q1** 五档是否支持 / 实际采样率 | 依次发 `SET_TIME_BASE 0..4`，读 `ACK_TB` 的 `DATA[0]` **和** 帧头 `byte7` | 5 次都回请求值；帧头跟随 |
| **Q2** 切档是否帧边界 / 丢几帧 | 发 `SET_TIME_BASE`，记录切档前后的 `TIME_BASE` 与 `SEQ` | 帧头 TB 全帧一致；`SEQ` 跳 2~3 后继续 +1 |
| **Q3** `ACK 0x90` 是否回实际档位 | 发 `SET_TIME_BASE 9` | 回 `ACK_TB 04`（当前值），帧头仍 4 |
| **Q4** 越界回 NACK 还是降级 | 同上，看 CMD 是 `0x80` 还是 `0x90` | **必须 `0x90`**（时基不 NACK）|
| **Q5** 是否严格等间隔 / 有无抽取 | `SET_TESTPAT 1` → 比两个 CRC32 → `SET_TESTPAT 0` | 两个 CRC32 都对（**只覆盖布局，不覆盖时间轴**）|
| **Q6** 帧率 / 两包是否连续 | 收 10 秒数完整帧；量同 SEQ 两包到达时间差 | 5ms 档 38.3 fps；两包间隔 **<1 ms** |
| **Q7** `TICK_MS` 含义 | 收 10 帧：同帧两包是否相同、帧间是否递增、间隔是否 25~50 ms | 同帧相同、帧间递增、间隔与帧率吻合 |
| **Q8** 关通道是否保布局 | 发 `SET_CH_ENABLE 0x01` | CH2 全 0、CH1 不变、帧长仍 1272 |
| **Q9** `TRIG_POS` 是否恒等于 `pre` | 发 `SET_TRIGGER`，读帧头 `[10..11]` | 等于 `pre`（`pre=50` → 50）；未找到时 `0xFFFF` |

**建议你们文档正文里的 9 个 `【待确认】` 标记直接删掉**，改成：

```
【已验证】<日期>·<谁>·证据：<命令> → <实际输出>
【待验证】判据：<怎么做> → <期望值>
```

**否则文档永远显示还有 9 项待确认，下一轮又会被从头问一遍。**

## 8. 唯一必须两边一起做的 2 项

这两项**任何一方都无法单独自证**，需要约定时间一起做（采集端需要提前预约板子）：

### 8.1 `dt` 时间轴校验

**为什么不能单方面做**：

- 采集端自发方波自己采 → 采样率偏了方波跟着偏，测不出来（评分表也明令禁止）
- 显示端只知道收到的点，不知道真实采样间隔

**做法**：

```
外部信号源 1000 Hz 方波 → 接 A0（CH2）
10ms/格：一屏 100 ms 应显示 10 个周期
5ms/格：  一屏  50 ms 应显示  5 个周期
1ms/格：  一屏  10 ms 应显示 10 个周期
判据：每档「周期数 ÷ 一屏时长」都 = 1000 Hz ±5%
```

### 8.2 触发静止性

```
信号同时接 A0（CH2）和 PB15（D3）
发 SET_TRIGGER [src=5(D3), edge=0(上升), level=0, pre=50]
判据：波形静止不滑、触发点标记在 10% 位置、帧头 TRIG_POS = 50
```
