# 双端通信协议规范

> **适用**：远程数据采集系统 · 采集端 ↔ 显示端
> **版本**：v1.2
> **日期**：2026-11-05
> **性质**：接口契约。本文档描述的全部行为已在采集端实现，并通过 PC 单元测试与真机验证（见 §12）。
>
> **显示端只需要一根网线。** 9 条控制命令与全部数据帧都走 UDP，
> USART6 只是可选备份链路，不接也能完整工作；
> 采集端的 USART1 是本地调试台（单字符命令），**不属于协议**，显示端永远不需要它。
>
> **本次（v1.2）相对 v1.1 的变化**：
> ① 新增 **§1.2 上电默认状态**（含实测值）
> ② 新增 **§3.2 码值→电压换算**（`提高 11` 必须按这个算，否则峰峰值会超差）
> ③ 新增 **§7.4 显示端必须做的事**（8 条，逐条可勾）
> ④ 新增 **§13 已知特性与注意事项**（任意沿、悬空通道、`pre` 取模、`SEQ` 回绕）
> ⑤ 串扰结论更正为**实测 ≤0.03%**（此前文档里的"1.5%"是测量伪像，见 §13.5）
> ⑥ 采集端默认 `pre` 由 0 改为 **250**

## 1. 系统概览

```
        ┌──────────────┐                      ┌──────────────┐
        │   采集端      │  以太网 / 串口        │   显示端      │
        │ STM32F746    │◄────────────────────►│ STM32F746    │
        │              │                      │              │
        │ ADC 双通道    │   数据帧 A5 5A ────►  │  波形显示     │
        │ GPIO 三路数字 │   (1272 B, 40 fps)   │  测量         │
        │              │                      │  存储导出     │
        │              │  ◄──── 控制帧 A5 5B  │  通道开关     │
        │              │   (6~38 B, 按需)      │  触发设置     │
        └──────────────┘                      └──────────────┘
```

| 链路 | 用途 | 默认 |
|---|---|---|
| 以太网 UDP | **主链路**，数据帧 + 控制帧 | 5 米以上 |
| USART6 | 备份链路，同样支持数据帧 + 控制帧 | **921600**，短线 |

两条链路**协议完全相同**。一条断了另一条照常工作。

### 1.1 显示端到底需要接什么

| 项目 | 显示端需要吗 | 说明 |
|---|---|---|
| **网线（UDP 5000）** | ✅ **必须，且只需要这个** | 数据帧 + 全部 9 条控制命令 |
| USART6 | ⬜ 可选 | 备份链路，不接也能完整工作 |
| 采集端 USART1 | ❌ **永远不需要** | 本地调试台（`0`~`4`、`i`、`d`、`W1000` 等单字符命令），**不属于协议** |

**结论：显示端一根网线接上就能拿到全部功能，不需要任何串口连线。**
采集端本地的 `u` / `n` / `b` 只是切换走哪条链路，默认 `n`（纯网口），显示端无需干预。

### 1.2 上电默认状态（实测，2026-11-05）

**采集端一上电就是这个状态，显示端可以用 `GET_STATUS` 读回来核对。**

| 项目 | 默认值 | 说明 |
|---|---|---|
| `TIME_BASE` | **2**（1 ms/格）| 五档中的中间档 |
| `CH_EN` | **0x1F** | 5 路**全部开启** |
| `RUN` | **1** | 上电即开始发帧 |
| 触发 | **关闭**（`SRC=0`、`EDGE=上升`、`LEVEL=2048`、`pre=250`）| 需要显示端主动 `SET_TRIGGER` 才生效 |
| 方波发生器 | **1000 Hz** | `SET_SQUARE` 可改，范围钳在 100~10000 |
| 数据源 | **真实 ADC** | 不是测试图案 |
| 测试图案模式 | **布局校验**（`SET_TESTPAT 1` 等价）| 需要时才发 `SET_TESTPAT` |
| 数据帧走向 | **只走 UDP** | 串口备份默认不发 |
| 命令接收 | **USART6 + UDP 都收** | 显示端走 UDP 即可 |

**由此得到的上电行为**：插上网线、上电之后，
显示端**什么都不用做**就会开始收到 1 ms/格、5 路全开的数据帧（约 35 帧/秒）。

**⚠️ 注意**：上电后 `CH_EN = 0x1F` 意味着**5 路全部在显示**。
如果只接了一部分信号源，没接的那几路会显示"另一路的影子"（见 §13.2）。
**显示端应在初始化时按实际接线发一次 `SET_CH_ENABLE`。**

## 2. 网络配置

| 项 | 值 |
|---|---|
| 采集端 IP | **`192.168.9.10`** |
| 显示端 IP | **`192.168.9.11`** |
| 子网掩码 | `255.255.255.0` |
| 网关 | `0.0.0.0` |
| DHCP | **关闭**（直连无服务器）|
| UDP 端口 | **双方都用 `5000`** |
| 连接 | 网线直连，MDI/MDIX 自适应，不需要交换机 |

双方都 `bind(0.0.0.0, 5000)`。因为 IP 不同，端口相同不冲突。

### 2.1 应答往哪回

**谁来的请求，应答就回给谁**：

| 请求来自 | 应答去向 |
|---|---|
| UDP | 回到**报文源 IP:端口**（不是固定地址）|
| USART6 | USART6 |

### 2.2 端口 5000 被占用时的处理

Windows 上 `nidmsrv`（National Instruments 服务）经常占着 UDP 5000，导致绑不上。

```
排查： Get-NetUDPEndpoint -LocalPort 5000
处理： 停掉该服务
```

> **只影响 PC 上的测试脚本。** 显示端是 STM32 + LwIP，不经过 Windows 协议栈，
> 不受这个占用影响。

---

### 2.3 链路路径选择（采集端本地选项）

采集端同时支持 **USART6（串口）** 和 **UDP（以太网）** 两条链路，帧格式完全相同。
默认**数据帧只走 UDP**，**命令两条都收**。

采集端串口调试台（USART1，115200）可以强制整条链路只走某一条：

| 命令 | 数据帧 | 命令接收 | 说明 |
|---|---|---|---|
| `u` | 只走 USART6 | 只收 USART6 | 纯串口链路 |
| `n` | 只走 UDP（**默认**）| 只收 UDP | 纯网口链路 |
| `b` | 两条都发 | 两条都收 | 冗余链路 |

**注意几点**：

1. **应答永远从命令进来的那条路回去** —— 与上面的设置无关。
   所以设成 `u` 之后从网口发的命令**不会有任何回应**（这正是"该路径已关闭"的表现）。
2. 遥测里 `mode=<发>/<收>` 显示当前设置，例如 `mode=2/2` 表示两条都只走 UDP。
3. 切到 `u` 之前请确认 USART6 有对端，否则数据帧发不出去（遥测 `UART6 err` 会一直涨）。
4. 这是**采集端本地调试选项**，不是协议命令 —— 显示端不需要也无法远程改。

## 3. 通道定义

| 协议名 | 物理量 | 引脚 | `CH_EN` 位 |
|---|---|---|---|
| `CH1` | 电位器 | PF10（Arduino **A1**）| bit0 |
| `CH2` | 麦克风 | PA0（Arduino **A0**）| bit1 |
| `D1` | 数字 1 | PB4（Arduino **D3**）| bit2 |
| `D2` | 数字 2 | PB14（Arduino **D12**）| bit3 |
| `D3` | 数字 3 | PB15（Arduino **D11**）| bit4 |

**命名对照**：本方案的 `D1/D2/D3` 对应课程评分表里的 `D0/D1/D2`。

### 3.1 `CH_EN` 的语义

- **数据帧永远包含全部 5 路**，帧长恒定 1272 字节，关闭通道不会让帧变小
- **关闭的通道在载荷里填 0**（模拟填 `0x0000`，数字对应位清 0）
- 显示端看到 0 就知道这一路没开，可以直接不画
- 显示端**也可以**用 `CH_EN` 提前跳过渲染，两种做法都行
- **关通道只影响载荷，不改变 ADC 的转换序列** —— 硬件仍然每个序列都转两路。
  实测通道间串扰**双向均 ≤0.03%（−70 dB 以下）**，可忽略。
  但**悬空输入**会显示另一路的"影子"（33~45%），这是悬空高阻输入的固有现象，
  不是串扰 —— 不用的通道请用 `CH_EN` 关掉。

### 3.2 码值 → 电压的换算（显示端必读）

**载荷里的模拟量是 12 位 ADC 码（0~4095），换算公式固定为：**

```
V = code × 3.3 / 4095          （单位：伏）
```

| 项 | 取值 | 说明 |
|---|---|---|
| 满量程 | **4095** | 不是 4096 —— 12 位 ADC 的最大码值是 4095 |
| 参考电压 | **3.3 V** | 标称值。实测 VDDA 可能在 3.28~3.32 V，引入 <0.7% 误差 |
| 量化精度 | 3.3/4095 = **0.806 mV/LSB** | 12 位分辨率 |

#### 峰峰值（`提高 11` 用）

```
Vpp = (code_high − code_low) × 3.3 / 4095
```

**`code_high` / `code_low` 必须用分位数，不能用 min/max：**

| 取法 | 说明 |
|---|---|
| ❌ `max − min` | **单个噪声尖峰就会把结果拉偏 1~2%**，而判据只有 5% |
| ✅ **99.5% 分位 − 0.5% 分位** | 与示波器读"稳定后的峰峰值"口径一致 |

**实测对照**（2 kHz 方波，峰峰 1854 码）：

```
原始 min/max   : 1103 / 2981  -> Vpp = 1.513 V
0.5%/99.5%分位 : 1123 / 2977  -> Vpp = 1.494 V   <- 用这个
两者差 1.3%
```

#### 三个必须避免的错误

| 错误 | 后果 |
|---|---|
| 用 `4096` 而不是 `4095` | 偏小 0.024%，影响很小但没必要 |
| 用 `max − min` | 噪声尖峰导致 Vpp 偏大 1~2% |
| **对数据做自动缩放后再显示测量值** | 测出的 Vpp 与实际输入无关，必然超差 |

#### 误差预算（判据 ≤5%）

| 来源 | 量级 |
|---|---|
| VDDA 偏差（3.28~3.32 V）| ≤0.7% |
| 分位数 vs min/max 的取法 | ≤1.3% |
| ADC 增益/偏置误差（未校准）| ≤1~2% |
| **合计** | **≤3%，余量足够** |

#### 验收时的对标方法

老师会用**示波器探头接 A0（PA0）、地夹接板子 GND、DC 耦合**读 Vpp 作为真值。
**示波器量的和 ADC 采的是同一个点**，所以这个比较是公平的。

> 示波器探头约 10~15 pF，麦克风模块输出阻抗通常 <1 kΩ
> → 截止频率 >10 MHz，对 200 Hz~2 kHz 无影响。

## 5. 控制帧（`A5 5B`）

### 5.1 格式

```
偏移:   0     1     2      3       4 .. 3+LEN       4+LEN   5+LEN
        A5    5B   LEN    CMD     DATA[LEN]         CRC_lo  CRC_hi
```

| 项 | 规则 |
|---|---|
| 整帧长度 | **`6 + LEN`** |
| `LEN` 范围 | 0 ~ 32（整帧 6 ~ 38 字节）|
| CRC 覆盖 | 偏移 `0` 到 `3+LEN`（含包头与 DATA，不含 CRC 本身）|
| CRC 字节序 | **小端** |

### 5.2 CRC-16/CCITT-FALSE

| 参数 | 值 |
|---|---|
| 多项式 | `0x1021` |
| 初值 | `0xFFFF` |
| refin / refout | `false` / `false` |
| xorout | `0x0000` |
| **自检** | `CRC16("123456789") == 0x29B1` |

Python 等价实现：`binascii.crc_hqx(data, 0xFFFF)`。

> STM32 的硬件 CRC 外设参数与此不同，**不要用**。

### 5.3 命令表

| CMD | 名称 | 方向 | DATA | 应答 |
|---|---|---|---|---|
| `0x01` | `HELLO` | 双向 | `[0x01]` | `0x81` |
| `0x02` | `PING` | 双向 | — | `0x82` |
| `0x03` | `GET_STATUS` | 显→采 | — | `0x83` |
| `0x10` | `SET_TIME_BASE` | 显→采 | `[档位 0..4]` | `0x90 [实际档位]` |
| `0x11` | `SET_CH_ENABLE` | 显→采 | `[掩码]` | `0x91 [实际掩码]` |
| `0x12` | `SET_TRIGGER` | 显→采 | `[src, edge, lvl_lo, lvl_hi, pre_lo, pre_hi]` | `0x92 [src, edge]` |
| `0x13` | `SET_RUN` | 显→采 | `[0/1]` | `0x93 [实际值]` |
| `0x14` | `SET_SQUARE` | 显→采 | `[Hz_lo, Hz_hi]` | `0x94 [Hz_lo, Hz_hi]` |
| `0x15` | `SET_TESTPAT` | 显→采 | `[0/1]` | `0x95 [实际值]` |
| `0x80` | `NACK` | 采→显 | `[错误码]` | — |
| `0x81` | `ACK_HELLO` | 采→显 | `[VER, TB, CH_EN, RUN, CAP]` | — |
| `0x82` | `PONG` | 采→显 | `[0x5A]` | — |
| `0x83` | `ACK_STATUS` | 采→显 | 9 字节，见 §5.5 | — |
| `0x90`~`0x94` | 各类 ACK | 采→显 | 见上 | — |

**所有 ACK 回的都是"实际生效的值"，不是回显。**
例如发 `SET_TIME_BASE 9`（越界）→ 回 `ACK_TB [当前档位]`，档位不变。

### 5.4 `SET_TRIGGER` 的 6 字节负载

| 偏移 | 字段 | 取值 |
|---|---|---|
| 0 | `src` | 0=关闭 1=CH1 2=CH2 3=D1 4=D2 5=D3 |
| 1 | `edge` | 0=上升 1=下降 2=任意 |
| 2-3 | `level` | 小端，ADC 码 0~4095（模拟源用；超出钳到 4095）|
| 4-5 | `pre` | 小端，预触发点数 |

应答 `0x92 [src, edge]`。参数非法回 `NACK 0x02`。

### 5.5 `ACK_STATUS` 的 9 字节

| 偏移 | 字段 |
|---|---|
| 0 | `TIME_BASE` 0..4 |
| 1 | `CH_EN` |
| 2 | `RUN` |
| 3 | `TRIG_SRC` 0..5 |
| 4 | `TRIG_EDGE` 0..2 |
| 5-6 | `TRIG_LEVEL` 小端。**数字触发源（`TRIG_SRC` 3/4/5）时恒为 0**，显示端忽略 |
| 7-8 | `SQUARE_HZ` 小端 |

### 5.6 `ACK_HELLO` 的 5 字节

| 偏移 | 字段 |
|---|---|
| 0 | `VER` = `0x01` |
| 1 | `TIME_BASE` |
| 2 | `CH_EN` |
| 3 | `RUN` |
| 4 | `CAP` 能力位 |

**握手一次就能把 UI 拉齐**，不必再单独发 `GET_STATUS`。两者都支持，任选。

### 5.7 能力位 `CAP`

| 位 | 含义 |
|---|---|
| `0x01` | `GET_STATUS` / `ACK_STATUS` |
| `0x02` | `SET_TRIGGER` / `ACK_TRIG` |
| `0x04` | `SET_SQUARE` / `ACK_SQ` |
| `0x08` | 数据帧 `[16..19]` 为 `TICK_MS` |
| `0x10` | 支持测试图案模式 |

采集端当前返回 **`0x1F`**。

### 5.8 错误码

| 码 | 含义 |
|---|---|
| `0x01` | 未知命令 |
| `0x02` | 参数越界 / 长度不足 |
| `0x03` | 版本不符 |
| `0x04` | 忙 / 未实现 |

## 6. 数据帧（`A5 5A`）

### 6.1 组成

| 段 | 长度 |
|---|---|
| 头 | 20 |
| 载荷 | 1250 |
| CRC16 | 2 |
| **合计** | **1272** |

一帧 **500 点**，拆成 `PART=0` 和 `PART=1` 两包，每包 250 点。

### 6.2 头部 20 字节

| 偏移 | 字节 | 字段 | 说明 |
|---|---|---|---|
| 0 | 1 | `MAGIC0` | `0xA5` |
| 1 | 1 | `MAGIC1` | `0x5A` |
| 2 | 1 | `VER` | `0x01` |
| 3 | 1 | `TYPE` | `0x20` |
| 4-5 | 2 | `SEQ` | 小端，帧号 |
| 6 | 1 | `PART` | 0 / 1 |
| 7 | 1 | `TIME_BASE` | 0..4 |
| 8 | 1 | `CH_EN` | 低 5 位有效 |
| 9 | 1 | `TRIG_FLAG` | **配置的触发源**（0=关 1=CH1 2=CH2 3=D1 4=D2 5=D3），低 3 位有效 |
| 10-11 | 2 | `TRIG_POS` | 小端。找到触发时 = **恒等于预触发点数 `pre`**；`0xFFFF` = 本帧无触发 |
| 12-13 | 2 | `NSAMP` | 恒 250 |
| 14-15 | 2 | `TRIG_LEVEL` | 小端 |
| 16-19 | 4 | `TICK_MS` | 小端，采集端发此帧时的本地毫秒 |

`SEQ` 是逻辑帧号，`TICK_MS` 是真实时间。两者一起用可以区分「帧丢了」和「板子卡了」。

### 6.2.1 `TRIG_FLAG` 与 `TRIG_POS` 的分工（**别搞混**）

这两个字段表达两件不同的事：

| 字段 | 表达什么 | 取值 |
|---|---|---|
| `TRIG_FLAG` | **配置的触发源是什么** | 0=关 1=CH1 2=CH2 3=D1 4=D2 5=D3 |
| `TRIG_POS` | **本帧有没有找到触发点** | `pre`（找到）/ `0xFFFF`（没找到）|

所以：

- `TRIG_FLAG = 2` 且 `TRIG_POS = 0xFFFF` → 配了 CH2 触发，**但本帧没找到触发点**
- `TRIG_FLAG = 2` 且 `TRIG_POS = 30` → 配了 CH2 触发，找到了，触发点在帧内第 30 点
- `TRIG_FLAG = 0` → 触发功能关闭

**`TRIG_FLAG` 永远等于配置值**，不会因为"本帧没触发"而变成 0。
「有没有触发」只看 `TRIG_POS` 是不是 `0xFFFF`。

### 6.2.2 `TRIG_POS` 是固定的，不会抖

触发开启时，采集端**每帧重新搜索**最近的触发点，但**帧窗口的起点跟着触发点一起移动**，
使得触发点**始终落在帧内第 `pre` 个样点**。

```
帧窗口 = [触发点 - pre,  触发点 - pre + 500)
                              ↑
                        触发点固定在这里
```

**所以 `TRIG_POS` 恒等于 `pre`**，波形在屏幕上**静止不动**。

显示端做锚点对齐时**不需要平滑**，直接按 `pre` 平移即可。

> 重叠模式下（相邻帧前进 250 点）这个性质不变：窗口起点变了，但触发点在窗口内的位置不变。

**没找到触发点时**（`TRIG_POS = 0xFFFF`），窗口退回自由运行（跟着写指针走），波形会滚动。

### 6.2.3 触发电平与数字源

`TRIG_LEVEL` 只对模拟源（CH1/CH2）有意义。
**数字触发源（D1/D2/D3）时该字段恒为 0**，显示端显示触发设置时应忽略它
（否则 UI 上会出现一个没有意义的电平值）。

### 6.3 载荷 1250 字节（**两块连续，不是逐点交织**）

```
整帧偏移 20    .. 1019    模拟块：250 点 × 4 字节
                          每点 = CH1_lo, CH1_hi, CH2_lo, CH2_hi

整帧偏移 1020  .. 1269    数字块：250 点 × 1 字节
                          低 3 位 = D3 D2 D1

整帧偏移 1270  .. 1271    CRC16（小端）
```

具体下标：

| 内容 | 下标公式 |
|---|---|
| CH1 第 `i` 点 | `pkt[20 + i*4 + 0]`（低） `pkt[20 + i*4 + 1]`（高）|
| CH2 第 `i` 点 | `pkt[20 + i*4 + 2]`（低） `pkt[20 + i*4 + 3]`（高）|
| 数字第 `i` 点 | `pkt[1020 + i]` |
| CRC | `pkt[1270]`（低） `pkt[1271]`（高）|

> **这里最容易写错**：模拟和数字是**两块连续**，不是每点 5 字节交织。
> 逐点交织是很自然的直觉，但不是本协议。

### 6.4 `SEQ` 与丢帧

| 项 | 规则 |
|---|---|
| 类型 | `uint16`，回绕 |
| 递增时机 | 每发完两包 +1（同一帧的两包 `SEQ` 相同）|
| 丢帧计算 | `丢失 = (SEQ_新 - SEQ_旧 - 1) & 0xFFFF` |
| 回绕周期 | 40 fps 下约 27 分钟 |
| 首帧 | 上电从 0 开始，第一次收到不算丢帧 |

### 6.5 两包配对规则

- 同一个 `SEQ` 的两包拼成 500 点
- `PART=1` 先到也要能正确入位
- **两包都齐了再读**：把「收到完整帧」作为唯一有效状态，不要读半帧

```c
/* 推荐写法 */
if (DISP_Feed(&ctx, pkt, len) == 1) {
    /* 这里读出来的 500 点是完整的一帧 */
    DISP_GetScreen(&ctx, &screen);
}
```

## 7. 会话状态机

### 7.1 采集端行为

| 项 | 规则 |
|---|---|
| HELLO | 上电立即发，每 1 s 一次，共 **3 次**；之后改为每 **3 s** 慢重试 |
| 进入 UP | 收到任何合法控制帧 |
| UP 后 | 每 **1 s** 发一次 `PING` |
| 超时 | **3000 ms** 收不到任何帧 → `LOST` |
| LOST 后 | 继续慢重试 HELLO |

### 7.2 `RUN=0` 时的行为

| 项目 | `RUN=0` |
|---|---|
| 数据帧 | **停发** |
| PING | **继续发**（1 s 一次）|
| 收命令 + 应答 | 正常 |
| ADC/DMA 采集 | 继续跑 |

**`RUN=0` 不会让显示端误判 LOST。**

### 7.3 显示端建议流程

1. 上电 → 发 `HELLO` 或等采集端的 `HELLO` → 从 `ACK_HELLO` 取状态对齐 UI
2. 3 s 收不到任何帧 → 判 LOST，UI 提示
3. LOST 期间继续发 `PING` 探活
4. 恢复后按需发一次 `GET_STATUS` 重新对齐

### 7.4 显示端必须做的事（逐条核对）

**这 8 条是采集端这边无法替显示端完成的。**

| # | 必须做 | 不做会怎样 |
|---|---|---|
| **1** | **按实际接线发一次 `SET_CH_ENABLE`** | 上电默认 5 路全开；没接的通道会显示"另一路的影子"（§13.2）|
| **2** | **按 `CH_EN` 裁剪显示** | 关闭的通道载荷全 0，不裁剪的话会画一条 0 线 |
| **3** | **两包按 `SEQ` 配对后再画** | 只拿一包会少一半点 |
| **4** | **`TRIG_POS != 0xFFFF` 时不要再做自己的对齐** | 双重对齐 → 波形按整周期跳（这是最容易被误判成"采集端抖动"的现象）|
| **5** | **触发方式默认选"上升沿"** | "任意沿"在对称信号上会跳半个周期（§13.1）|
| **6** | **电压按 §3.2 换算：`× 3.3 / 4095`** | `提高 11` 的峰峰值会超差 |
| **7** | **峰峰值用 99.5% − 0.5% 分位，不用 min/max** | 噪声尖峰让 Vpp 偏大 1~2%，判据只有 5% |
| **8** | **`SEQ` 按 `uint16` 回绕处理** | 连续跑 28.5 分钟后的丢帧统计会错（画面不受影响）|

**另外三条"不要"**：

- **不要**对接收到的数据做自动缩放后再显示测量值（测出的 Vpp 与输入无关）
- **不要**假设 `pre` 一定等于你上次设的值 —— 采集端会 `pre % 500`（§13.3）
- **不要**在 LOST 期间停止发 `PING`，否则恢复会很慢

## 8. 收包与分流

### 8.1 UDP 收包必须先按包头分流

```c
if (len < 2)              { bad++; }
else if (p[0] != 0xA5)    { bad++; }
else if (p[1] == 0x5A)    { DISP_Feed(&ctx, p, len); }   /* 数据帧 */
else if (p[1] == 0x5B)    { CMD_Handle(&ctx, p, len); }   /* 控制帧 */
else                      { bad++; }
```

**`bad` 只统计「既不是 `0x5A` 也不是 `0x5B`」或校验失败的包。**
控制帧不是坏帧，不能计入 `bad`。

### 8.2 重复命令去重

采集端实现了 **200 ms 去重窗口**：同一 `(CMD, DATA)` 在 200 ms 内重复到达时，
**不重复执行**，直接把上一次的应答原样重发。

对显示端的含义：

- 可以放心重发，不会重复执行
- 但重发的应答和第一次**完全一样**，无法从中区分「新应答」和「重放」
- 所以不要用「收到 ACK」判断命令被执行了几次

### 8.3 重发建议

| 参数 | 建议 |
|---|---|
| 重发间隔 | 500 ms |
| 最多重发 | 3 次 |
| 总超时 | 2 s |

## 9. 帧率与带宽

### 9.1 发送条件

采集端在两个条件**同时满足**时发一帧：

```
攒够 250 个新样点   且   距上次发送 >= 25 ms
```

### 9.2 各档位的实际帧率

| 档位 | 每格 | 250 点需要 | 25 ms 门限 | **实际帧率** | 相邻帧关系 |
|---|---|---|---|---|---|
| 0 | 10 ms | 50 ms | — | **20 fps** | 50% 重叠 |
| 1 | 5 ms | 25 ms | 25 ms | **40 fps** | 50% 重叠 |
| 2 | 1 ms | 5 ms | 25 ms | **40 fps** | 无重叠，跳跃 2.5 屏 |
| 3 | 500 µs | 2.5 ms | 25 ms | **40 fps** | 无重叠，跳跃 5 屏 |
| 4 | 100 µs | 0.5 ms | 25 ms | **40 fps** | 无重叠，跳跃 25 屏 |

- **每一档都不低于 20 fps**
- 档位 1 的 250 点采集耗时正好 25 ms，与门限相等。实测时刻通常略大于 25 ms 所以能通过；
  若出现 20/40 fps 抖动，把门限降到 23 ms 即可（不影响其他档位）
- 慢档（10 ms / 5 ms）：每帧是「最近 500 点」，相邻帧有一半是新的 → 平滑滚动
- 快档（1 ms 及更快）：一帧覆盖的时间短于一帧间隔，波形会「跳」。
  **这是正常现象**，打开触发即可稳定显示

### 9.3 带宽

| 项 | 数值 |
|---|---|
| 每帧 | `2 × 1272 = 2544` 字节 |
| 档位 1（40 fps）| 101.8 KB/s ≈ 814 kbps |
| 档位 0（20 fps）| 50.9 KB/s |
| 档位 2~4（40 fps）| 101.8 KB/s ≈ 814 kbps |
| 100 Mbps 以太网占用 | **< 1%** |

> 允许重叠（每 25 ms 发一次最近 500 点）只让**档位 1 的带宽从 50.9 翻到 101.8 kB/s**。
> 档位 2~4 本来就是 40 fps，带宽不变；档位 0 仍受采样率限制（50 ms 才够 250 点）。

带宽不是瓶颈，所以没有做载荷压缩。

### 9.4 USART6 备份链路的带宽

一屏 = 2 包 × 1272 = 2544 字节，8N1 每字节 10 bit：

| 波特率 | 一屏耗时 | 最高帧率 |
|---|---|---|
| 115200 | 220.8 ms | 4.5 fps |
| **921600（当前）** | **27.6 ms** | **36.2 fps** |
| 1500000 | 17.0 ms | 59.0 fps |

当前 USART6 = **921600**，最高 36.2 fps，高于 20 fps 的要求；
若需要满 40 fps，改成 1500000（APB2 = 108 MHz 时 USARTDIV 恰为 4.5，分频零误差）。

**注意：USART6 只发不出的帧会被丢弃，不会排队。** 所以它的实际帧率由自身带宽决定（36 fps），
与 UDP 的 40 fps 相互独立，不会互相拖慢。

## 10. 测试图案模式（`SET_TESTPAT`）

采集端可以发**写死的确定性图案**代替真实 ADC 数据。

**用途：这是双方验证接口的官方手段。** 图案值是**已知答案**，接收端解出来后
和下面的标准答案逐字节比对 —— 一个 CRC32 对上，就说明载荷布局、字节序、
通道顺序、位打包、PART 划分**全部正确**，不需要再就这些问题做任何沟通。

### 10.1 命令

```
显示端 → 采集端：  A5 5B 01 15 <00|01> CRC16        (0=真实ADC  1=测试图案)
采集端 → 显示端：  A5 5B 01 95 <00|01> CRC16        (回实际生效值)
```

| 规则 | 行为 |
|---|---|
| `DATA[0] = 0` | 切回真实 ADC + GPIOB->IDR |
| `DATA[0] = 1` | 切到**布局校验**图案（按采样点定义，与档位无关），CRC32 恒定 |
| `DATA[0] = 2` | 切到**时基校验**图案（按固定频率生成，换档位画面会变）|
| `DATA[0]` 为其它值 | **保持当前状态**，`ACK_TP` 回实际值（不 NACK）|
| `LEN = 0` | `NACK 0x02`（长度不足）|
| 不支持该功能 | `NACK 0x04`（忙）|

**切换立即生效**，不需要等帧边界（图案是静态的，不存在"半帧混合"）。

### 10.1.1 两种图案模式（**分清楚用哪个**）

| 模式 | 图案按什么定义 | 换档位时画面 | 用途 |
|---|---|---|---|
| **1 布局校验** | **按采样点**（`per = 100` 个点）| **不变**（恒 5 个周期）| 验载荷解析（CRC32 恒定） |
| **2 时基校验** | **按固定频率**（`per = 采样率 / 目标频率`）| **会变** | 验时基，能看出换档生效 |

> 模式 1 的两个 CRC32 与档位无关，所以只用一组就能校验任何档位的解析。
> 模式 2 不做 CRC 校验（它会随档位变），只用来看波形。

### 10.2 图案定义（默认预设，`SET_TESTPAT 1` 后即为这一组）

| 通道 | 内容 |
|---|---|
| `CH1`（电位器）| 三角波，`amp = 4095`、`per = 100`、中心 2048 |
| `CH2`（麦克风）| 正弦表 64 点（见下），中心 2048，幅度 ±1600 |
| `D1` | `{0,1}` 循环 → `k % 2 == 1` |
| `D2` | `{0,0,1}` 循环 → `k % 3 == 2` |
| `D3` | `{0,0,0,1}` 循环 → `k % 4 == 3` |

`k` = 该点在 500 点整帧中的序号（PART0 是 0..249，PART1 是 250..499），
**不是**在包内的序号。

**三角波公式**（整数运算，先乘后除）：

```
half = 100 / 2                      // = 50
p    = k % 100
d    = (p < half) ? p : (100 - p)
lo   = 2048 - (4095 + 1) / 2        // = 0
v    = lo + (4095 * d) / half       // 截断取整
if (v > 4095) v = 4095
```

**正弦表 64 点**（原样照抄）：

```
2048, 2205, 2360, 2512, 2660, 2802, 2937, 3063,
3179, 3285, 3378, 3459, 3526, 3579, 3617, 3640,
3648, 3640, 3617, 3579, 3526, 3459, 3378, 3285,
3179, 3063, 2937, 2802, 2660, 2512, 2360, 2205,
2048, 1891, 1736, 1584, 1436, 1294, 1159, 1033,
 917,  811,  718,  637,  570,  517,  479,  456,
 448,  456,  479,  517,  570,  637,  718,  811,
 917, 1033, 1159, 1294, 1436, 1584, 1736, 1891
```

**模式 2 的目标频率可调**（采集端串口调试台，不属于协议）：

```
Y1000<回车>   指定 1000 Hz
Y0<回车>      自动：per 固定 60，一屏恒 8.3 个周期，任何档位都量得到
```

**一定要注意**：一屏时间窗从 100 ms（10ms/格）到 1 ms（100µs/格）跨了 **100 倍**，
**不可能用一个固定频率同时适合两端**。
所以：想「任何档位都看得见」就用 `Y0`；想「验某个具体频率」就用 `Y<数字>`。

**正弦表自检量**（用来确认表没抄错）：`sum == 131072`，`xor == 0x0F80`

### 10.3 ★ 标准答案（验收用，请直接比对这两个数）

对**解出来的 1250 字节载荷**（帧内偏移 `20..1269`，不含帧头和 CRC）
算 CRC32（标准 zlib / Python `binascii.crc32`，多项式 0xEDB88320 反射，初值 0xFFFFFFFF，末尾取反）：

| PART | 覆盖的点 | 载荷长度 | **CRC32** |
|---|---|---|---|
| `0` | `k = 0..249` | 1250 B | **`0xAA003E01`** |
| `1` | `k = 250..499` | 1250 B | **`0x753D82DE`** |

参考实现：

```python
import binascii, struct
ok = (binascii.crc32(payload) & 0xFFFFFFFF) == (0xAA003E01 if part == 0 else 0x753D82DE)
```

**这两个数对上 = 下列各项全部正确**：

载荷是两块连续（不是逐点交织）· 模拟块内部 CH1 在前 CH2 在后 ·
16 位小端字节序 · 数字块起始偏移 1020 · 数字位打包 bit0=D1 ·
PART0/PART1 各覆盖 250 点

对不上时按 §10.4 的前 16 点表定位。

## 13. 已知特性与注意事项

**以下都是"设计如此"或"物理固有"，不是缺陷。写在这里是为了避免双方误判。**

### 13.1 「任意沿」触发在对称信号上会跳半个周期

`TRIG_EDGE_EITHER` 模式会锁到"任意一个沿"。对 50% 占空比的方波，
每个周期有两个沿，采集端可能锁到上升沿、也可能锁到下降沿 →
**波形会在相隔半个周期的两个位置之间切换。**

**真实示波器同样如此**，需要 holdoff 才稳定；本系统未实现 holdoff。

**建议**：显示端把触发方式的**默认值设为"上升沿"**，
「任意沿」留给"只关心有没有边沿、不关心相位"的场合。

### 13.2 悬空输入会显示"另一路的影子"

未接信号的通道，其读数是**高阻悬空引脚的残留电荷**，
表现为另一路信号的缩小副本（实测 33~45%）。

**这是任何 ADC 的固有现象，不是通道间串扰。**

| 做法 | 结果 |
|---|---|
| 通道开着、输入悬空 | 会看到影子 |
| **`SET_CH_ENABLE` 关掉该通道** | **载荷填 0，看不到影子** ✅ |
| 硬件上把输入脚接 GND | 也看不到影子 |

**建议**：显示端初始化时按实际接线发一次 `SET_CH_ENABLE`（见 §7.4 第 1 条）。

### 13.3 `pre` 会被自动取模

`SET_TRIGGER` 的 `pre` 允许 0~65535，采集端内部按 `pre % 500` 使用。
所以发 `pre=65535` 等价于 `pre=35`，**不会越界、不会崩，但 `TRIG_POS` 会报 35**。

**建议**：显示端把 `pre` 限制在 **0~499**。

**上电默认 `pre = 250`**（触发点在帧正中）。若不设 `pre` 直接开触发，
`TRIG_POS` 会是 250。

### 13.4 关通道不会停止 ADC 转换

`CH_EN` 只影响**载荷**（关闭的通道填 0），ADC 仍然每个序列转换两路。
这是有意的设计：保持帧长恒定、索引不变。

对显示端没有影响（关闭的通道本来就填 0）。

### 13.5 通道间串扰的最终结论：≤0.03%

**2026-11-05 用 500 Hz + 2000 Hz 双路方波实测：**

```
CH2(2000Hz) → CH1 = 0.02%  (−72.2 dB)
CH1(500Hz)  → CH2 = 0.03%  (−70.3 dB)
```

**双向都低于噪声底，不存在可测的通道间串扰。**

> **历史更正**：早期曾测到"32% 串扰"，经复核是**频谱测量伪像** ——
> 700 Hz 方波的三次谐波（2100 Hz）经 Hann 窗泄漏进 2000 Hz 的测量 bin
> （bin 间隔 100 Hz，泄漏比 0.5，四次比值全部命中理论值）。
> 原始数据保留在 `数据验证区/`，详见《专题-串扰定位-20261105.md》。
>
> **对显示端的唯一要求**：不要把 CH1 的纵轴放大到极限，否则会看到 ADC 本身的噪声。

### 13.6 `SEQ` 是 16 位，28.5 分钟回绕

`SEQ` 从 0 递增到 65535 后回到 0。按 35 fps 计算，**约 28.5 分钟回绕一次**。

**建议**：显示端按 `uint16` 计算帧间隔：
`gap = (uint16)(seq_new - seq_old)`，不要直接减。

### 13.7 USART6 备份链路未经端到端验证

采集端代码里有 USART6 的数据/命令通路，但**从未在真实两端之间跑通**
（遥测里 `UART6 ok=0 err=1`）。

**验收演示请只用网线。** 如果被问到，可以说明"USART6 为预留备份接口，本设计以以太网为主链路"。

**验收时不要按采集端串口的 `u` 键** —— 那会把数据帧切到未验证的 USART6 上。

### 13.8 10 ms 档帧率约 19 fps

这是该档位的**设计结果**：一屏 100 ms，每次前进半帧 50 ms → 约 20 fps。

`提高 9`（通信距离与刷新率）考核的是**每格 5 ms 档**，该档实测 **35.7 fps**，
远高于要求的 20 fps。**10 ms 档的 19 fps 不构成"卡顿"。**
