### 2.2 帧率方案：**选 B（允许重叠）**

原文档的帧率表只计算了方案 A。补充方案 B（`n >= 250` 即发）的推导：

| 档位 | 窗口时长 | 250 点采集耗时 | 25 ms 门限 | **A 帧率** | **B 帧率** |
|---|---|---|---|---|---|
| 0（10 ms/格） | 100 ms | 50 ms | 25 ms | 10 fps | **20 fps** |
| 1（5 ms/格） | 50 ms | **25 ms** | 25 ms | 20 fps ⚠️ | **40 fps** |
| 2（1 ms/格） | 10 ms | 5 ms | 25 ms | 40 fps | 40 fps |
| 3（500 µs/格） | 5 ms | 2.5 ms | 25 ms | 40 fps | 40 fps |
| 4（100 µs/格） | 1 ms | 0.5 ms | 25 ms | 40 fps | 40 fps |

**选 B 的理由**：

1. 方案 A 在 5 ms 档正好 20 fps，**评分要求"不低于 20 帧/秒"，实测只要掉一帧就不达标**，风险不可接受
2. 方案 B 让所有档位 ≥ 20 fps，5 ms 档达到 40 fps，有 2 倍余量
3. 协议结构不变，显示端不需要改解析逻辑（仍收两包拼 500 点）
4. 带宽代价只发生在档位 1（50.9 → 101.8 kB/s）；档位 2~4 本来就是 40 fps，带宽不变

**选 B 的前提（显示端附加条件）**：

B 模式下每 25 ms 只前进半屏（250 点）。如果显示端不做对齐，画面会持续"滚动"。因此显示端会实现**基于 `TRIG_POS` 的锚点对齐**：触发开启时把触发点平移到固定位置，波形保持静止。

> 这一条同时回答了第 3.2 节的疑问——请对方确认重叠模式下 `TRIG_POS` 的行为。

**实施提醒（档位 1 的门限边界）**：

档位 1 的 250 点采集耗时正好 25 ms，与门限值相等。由于 DAC/ADC 启动延迟与检查周期，实测时刻通常略大于 25 ms，可以通过；但建议实测确认稳定在 40 fps。若出现 20/40 fps 抖动，把门限降到 **23 ms** 即可，不影响其他档位。

### 2.3 `CH_EN` 裁剪：**确认由显示端实现**

显示端会按 `CH_EN` 位控制绘制。位定义确认：

| 位 | 通道 | 显示端 UI 标签 |
|---|---|---|
| bit0 | CH1（电位器） | CH1 |
| bit1 | CH2（麦克风） | CH2 |
| bit2 | D1 | D0 |
| bit3 | D2 | D1 |
| bit4 | D3 | D2 |

**附加约束**（请确认）：关闭某通道时，**该通道的坐标位置保留，其余通道位置不变**。即 CH1 关闭后 CH1 波形区域空白，CH2/数字通道仍在其固定位置，不重排布局。这样才能满足"其余不受影响"。

### 2.4 `CAP` 能力位：**全要（`0x1F`），但 `HELLO` 不扩字段**

显示端会使用全部 5 位：

| 位 | 用途 |
|---|---|
| `0x01` | 进入 UP 后发 `GET_STATUS` |
| `0x02` | 启用触发菜单与 `SET_TRIGGER` |
| `0x04` | 启用方波频率设置 |
| `0x08` | 按 `TICK_MS` 计算帧间隔与卡顿 |
| `0x10` | 验收时切换测试图案逐点核对 |

**但 `HELLO` 的 DATA 不扩展能力位**。理由：

- `HELLO` 现为 `[VER]`（`LEN=1`），扩成 2 字节会改动采集端解析逻辑
- 显示端能力是固定的，不需要协商
- `HELLO_ACK` 的单向 `CAP` 已足够

若后期确需双向声明，建议新增独立命令，不要改动 `HELLO` 结构。

### 2.5 通道命名：**同意**

```
协议 D1/D2/D3  =  评分表 D0/D1/D2
```

显示端 UI 与报告统一使用 `D0/D1/D2`（与评分表一致），协议层做一次映射。两端报告都加这一句说明。

## 3. 需澄清的 3 点

### 3.1 `TRIG_FLAG` 语义歧义（**阻塞显示端实现，请优先回复**）

§6.2 写"`TRIG_FLAG` = 触发源（0=本次无触发）"，存在两种解读：

| 解读 | 配置源=CH2 且本帧触发时，该字节的值 |
|---|---|
| 甲：表示"是否有触发" | `1` |
| 乙：表示"触发源" | `2` |

两种解读会让显示端判错。建议明确为**乙**：

```
TRIG_FLAG = 配置的触发源（1=CH1, 2=CH2, 3=D1, 4=D2, 5=D3）
TRIG_POS  = 0xFFFF 表示本帧未找到触发点（是否触发只由 TRIG_POS 表达）
```

这样"源"和"有没有触发"分成两个字段，语义不重叠。

### 3.2 重叠模式下 `TRIG_POS` 是否稳定

方案 B 相邻帧重叠 250 点，同一触发事件在两帧中的位置会相差 250 点。

请确认：**每帧的 `TRIG_POS` 是重新搜索得到（位置会变），还是固定在窗口内的某个位置？**

- 若每帧重新搜索：显示端对齐算法需要加平滑（否则锚点抖动）
- 若固定：对齐直接平移即可

### 3.3 数字触发源时的 `TRIG_LEVEL`

`ACK_STATUS` 的 `TRIG_LEVEL` 定义为"ADC 码 0..4095"。当 `TRIG_SRC = 3/4/5`（D1/D2/D3）时，该字段应填什么？

建议明确规定：**数字源时填 0，显示端忽略该字段**。否则 UI 会显示一个无意义的电平值。
